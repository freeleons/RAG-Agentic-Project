LLM Architecture — Support Triage Agent

How the agent backend, AnythingLLM, and Ollama fit together — and the path a question travels to become a grounded answer.

The key relationship: Ollama wears two hats. There is one model server (Ollama, llama3.1:8b on port 11434) but it is called by two different clients for two different jobs: ① the Flask agent calls it to reason — pick tools, form arguments, and write final answers — and ② AnythingLLM calls it to generate grounded answers from retrieved document chunks when the agent uses the search_knowledge tool. AnythingLLM never talks to the agent's loop; Ollama never does retrieval. Retrieval (embedding + vector search) happens entirely inside AnythingLLM.

How one question gets answered

Example goal: “What does the remote-work policy say about equipment?”

Why the loop asks Ollama twice. Call 2 is the model deciding — it sees the goal and the tool schemas and emits a structured tool call. Call 9 is the model concluding — it sees the tool's result (wrapped in <tool_result> delimiters, treated as data, never instructions) and writes the answer for the user. In between, call 6 is a completely separate conversation: AnythingLLM's own prompt, built from your embedded documents. If the agent needs more information, steps 2–8 repeat — bounded by MAX_AGENT_STEPS.
